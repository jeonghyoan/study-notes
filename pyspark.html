import로 라이브러리를 로드하고 as(alias, 별칭)로 짧은 이름을 붙임. matplotlib도 같은 방식.

# [마스터 · JupyterLab 노트북 셀 · sparkuser]
import pandas as pd   # 데이터 조작 — pd라는 별칭
import numpy as np    # 수치 데이터 고속 처리 — np라는 별칭

코드는 직접 쓰기보다 생성 도구로 만든 코드를 실행하는 방식. 생성 도구가 넣어 준 위쪽 import 줄(random 등)도 같은 로드 방식.

pandas — 2차원 구조 데이터

항목내용주의·이유
다루는 데이터2차원 구조 데이터 — 표 형태의 조작·연산·출력그래프 출력도 가능하지만 시각화는 이 노트의 범위 밖
학습 자료 읽기csv·xlsx·xls 파일을 절대경로로 읽는 방식이 학습 위주대학·IT 전공 학습 중심 — Spark까지 다루는 실무에서는 취급하지 않음
이 노트의 방식csv 대신 DB(MySQL·PostgreSQL)에 연결해 핸들링csv는 개발자 쪽 작업, 필요하면 별도 특강 대상
선행 지식SELECT * FROM·JOIN 등 쿼리문모르면 같은 질문만 반복 — Spark까지 가면 특히 필수

numpy — 수치 연산

항목내용주의·이유
강점다차원 배열을 빠르게 처리 — 앞서 배운 배열과 같은 개념분산 데이터 처리에서 숫자 데이터 고속 처리에 사용
쓰는 이유파이썬 메모리를 효율적으로 관리서버에 설치하지 않으면 처리를 한참 기다리는 서버가 됨
역할 범위라이브러리는 프로세스를 돌릴 때 돕는 보조 역할연산 자체는 Spark 클러스터가 담당 (spark.html 2장)

matplotlib — 그래프(다루지 않음)

항목내용주의·이유
기능선·막대·원 그래프, 산점도 등 도식화표를 보기 좋게 만드는 작업은 주로 에이전트반·아키텍처 쪽
이 노트의 목적메모리를 잘 관리해 빠르게 연산하고 빠르게 결과를 얻는 것그래프는 목표가 아님 — pandas·numpy 중심

# [spark-master 컨테이너 · VS Code 노트북 spark_basic2 · root]
# 점수를 학점으로 바꾸는 파이썬 함수 — 입력은 숫자, 반환은 문자
def jumsu(a):
    if a >= 90:      # 90 이상
        return "A+"
    elif a >= 70:    # 70 이상
        return "B+"
    elif a >= 60:    # 60 이상
        return "C+"
    else:            # 60 미만
        return "D"

# 함수를 UDF로 등록 — 두 번째 인자가 반환 타입(StringType)
jumsu_udf = fn.udf(jumsu, StringType())

# (85,) 처럼 콤마를 붙여야 원소 1개짜리 튜플 — 한 괄호가 한 행, 컬럼명은 jumsu
df = spark.createDataFrame([(85,),(92,),(76,)],["jumsu"])

# 조건에 맞는 return 값이 grade 라는 새 컬럼으로 나옴
result = df.withColumn("grade",jumsu_udf(df["jumsu"]))

result.show()
spark.stop()

UDF 개념

항목내용주의·이유
정의UDF = User Defined Function = 사용자 정의 함수 — 함수를 등록해 결과 값을 컬럼으로 받아 옴Spark 내장 함수에 없는 계산을 직접 만들 때 씀
등록 위치functions(fn) 안의 fn.udf(함수, 반환타입)미리 선언한 함수를 넘겨야 함
반환 타입문자로 리턴하면 StringType, 숫자로 리턴하면 IntegerType처럼 …Type을 붙여 지정생략하면 기본값 StringType이 적용 — 의도한 타입이면 명시하는 것이 안전
시그니처pyspark.sql.functions.udf의 인자는 함수와 반환 타입 — returnType=StringType()이 기본값UDF는 사용자 정의 함수를 등록하는 기능 — 자료형 변환 도구가 아님. 컬럼 형 변환은 Column.cast를 씀

숫자를 반환하는 UDF

# [spark-master 컨테이너 · VS Code 노트북 spark_basic3 · root]
# 열 2개짜리 간단한 데이터 — 이름과 점수 (컬럼명은 영문)
data = [("홍길동",65),("강감찬",80),("유관순",100)]
df = spark.createDataFrame(data, ["name","jumsu"])

# ① 일반 파이썬 함수 — 점수를 2배로
def testfn(a):
    return a * 2

# ② 반환 값이 숫자이므로 IntegerType으로 등록 (함수, 반환 타입)
result_udf = fn.udf(testfn, t.IntegerType())

# ③ 대상은 이름이 아니라 점수 컬럼 — fn.col로 넘김
result = df.withColumn("2배수", result_udf(fn.col("jumsu")))

result.show()          # 2배수 컬럼에 130·160·200
spark.stop()
단계내용주의·이유
① 함수점수를 받아 2배를 return하는 일반 파이썬 함수def까지는 일반 파이썬 코드 — UDF는 반환 타입을 쓰는 부분부터
② 등록fn.udf(함수, 타입)의 결과를 변수(result_udf)에 담아 씀반환 값이 숫자라 t.IntegerType() — 문자를 반환할 때 StringType을 쓴 것과 같은 자리
③ 적용df.withColumn("2배수", …)로 새 컬럼 생성넘길 대상은 이름이 아니라 컬럼 — fn.col("컬럼명")
새 컬럼명한글 이름(2배수)도 사용 가능결과 확인이 쉬움
변수 이름결과는 앞에서 쓴 df와 다른 이름(result)에 담음원본 DataFrame을 덮어쓰지 않음
실행 결과2배수 컬럼에 130·160·20065·80·100의 2배

UDF 규칙

규칙내용이유

    ksum, kcnt = rtd.get(k, (0, 0))
    # 합계에 값 더하기, 건수 1 증가
    rtd[k] = (ksum + v, kcnt + 1)
# 딕셔너리를 (키, (합계, 건수)) 목록으로 변환해 출력
rtd_cnt = list(rtd.items())
print("결과:", rtd_cnt)

정의동일한 이름(데이터)끼리 묶어 그룹화하는 함수 — 같은 그룹이 있을 때 합계를 냄그룹 앞에 컬럼을 붙여 구분할 수도 있음
실무 예상품명이 같은 것끼리만 합산(상품별), 월별 합계사용자명 대신 product 컬럼으로 하면 상품별 합계
GROUP BY의 역할행을 그룹별로 묶어 그룹당 집계 한 행을 만드는 것특정 월만 뽑는 것은 WHERE의 역할 — GROUP BY가 아님
sum의 위치같은 그룹으로 묶인 뒤 합계를 내는 함수단독으로 따로 쓰는 일은 거의 없고, select로 별도 추출하는 경우는 있음
중요도이 묶음에서 groupBy가 가장 중요집계의 기본 단위
실수·실험결과해결·메모
aa.groupBy("점수").sum("영어")에러 — "점수"라는 컬럼이 없음그룹으로 묶을 컬럼은 실제 존재하는 컬럼이어야 함 → "이름"으로 변경
이름이 모두 다를 때같은 그룹이 없어 각 행이 그대로 한 줄씩 나옴합계가 보이지 않는 것이 정상
동일인 연습 — ["김남주",80,20] 행 추가원래 김남주는 60·80 → 영어 합계 140점(60+80)같은 이름이 두 행일 때 합계가 합쳐지는지 확인

# [spark-master 컨테이너 · JupyterLab 노트북 셀 · root]
import pandas as pd                                 # 응답 JSON 을 표로 받는 그릇
import requests                                     # HTTP 요청 라이브러리

api_url = "http://192.168.222.5:11111/travel"       # API 주소 — 포트까지 포함
res = requests.get(api_url)                         # GET 요청, 결과는 response 객체
res.raise_for_status()                              # 4xx·5xx 응답이면 예외로 중단
jsondata = res.json()                               # JSON 문자열 → 파이썬 list/dict
data = pd.DataFrame(jsondata)                       # 파이썬 객체 → pandas 데이터 프레임
df = spark.createDataFrame(data)                    # pandas → Spark 데이터 프레임
df.createOrReplaceTempView("travel")                # 임시 뷰(가상 테이블) 생성 — 이름은 자유
spark.sql("select * from travel limit 10").show()   # SQL 로 조회 — Spark 는 limit 콤마 불가
spark.stop()                                        # 세션 종료

raise_for_status에러 응답이면 그 자리에서 예외없으면 500 응답 본문을 데이터로 착각해 다음 줄에서 엉뚱한 에러

왜 엔진으로 바꾸는가

항목내용주의·이유
계기psycopg2 단독 연결을 pandas에 넘기던 코드를 엔진 방식으로 교체앞 실습에서 나온 연결 관련 경고·에러를 정리하는 작업
pandas 요구pandas는 sqlite3 외 DB에는 SQLAlchemy 연결 객체를 요구원시 psycopg2 연결(DBAPI2)은 지원 대상이 아님 — 엔진이 성능을 높이는 것이 아니라 pandas가 요구하는 연결 형태를 맞추는 것 (pandas read_sql)
SQLAlchemySQL과 파이썬을 이어 주는 라이브러리접속 문자열과 스키마 옵션을 한 객체에 담음
드라이버내부 드라이버로 psycopg2를 그대로 사용접속 문자열의 postgresql+psycopg2 — psycopg2 설치와 import는 유지(spark.html 22장)
변경 범위import 구간 + 접속부(host·database·user·password·port·options 변수, conn 생성부)SparkSession 생성과 쿼리 후 출력부는 그대로

항목내용주의·이유
종료 함수psycopg2 단독은 conn.close(), SQLAlchemy 엔진은 dbinfo.dispose()엔진에 close()를 쓰면 에러 — 엔진 객체에 close()가 없음
실행 결과연결됨 출력, 에러 없이 데이터 출력서버가 느린 상태에서도 동작
기존 방식psycopg2 단독 연결도 계속 사용 가능연결 실패가 서버 부하로 이어지는 문제는 아님
dispose풀에 남은 연결까지 닫음다시 쓰려면 엔진을 새로 만듦

# [spark-master 컨테이너 · JupyterLab 노트북 셀 · root]
# psycopg2 버전 문제가 날 때 — 쿼리 문자열을 text() 로 감쌈
from sqlalchemy import text
pdf = pd.read_sql(text(query), con=conn)   # conn 은 with 블록 안에서
항목내용주의·이유
문법with engine.connect() as conn: — engine 자리에 엔진 변수(dbinfo)블록 안에서만 conn 사용
with 동작블록이 끝나면 연결은 풀로 반환될 뿐, DB 연결은 풀에 남아 있음풀의 연결을 완전히 닫는 것은 dispose() (SQLAlchemy connections, pooling)
쓰는 이유close·dispose를 깜빡해 나는 에러를 막으려는 개발자 방식with를 쓰면 반환은 자동
어려우면dbinfo.dispose()만 써도 됨close()만 쓰지 않으면 됨
text()SQLAlchemy로 실행할 때 쿼리 문자열을 감쌈psycopg2 버전 문제 해결
엔진 종료 — SQLAlchemy 엔진에는 close()가 없어 에러. dispose()가 풀까지 정리하는 종료 함수이고, with 블록은 연결을 풀에 반납할 뿐 완전 종료가 아님
pandas 연결 형태 — sqlite3 외 DB에 원시 DBAPI 연결을 넘기면 미지원·경고. postgresql+psycopg2 같은 SQLAlchemy 엔진으로 넘기는 것이 pandas가 요구하는 형태

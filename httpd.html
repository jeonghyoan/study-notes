웹 / WAS / Node 구분 · 호스팅 ≠ 클라우드

패키지명에 jsp·tomcat·spring·war가 있으면 WAS, 없으면 웹(Apache httpd·Nginx), node는 Node. 웹호스팅은 클라우드 안의 작은 단위. 개인정보를 받는 사이트는 HTTPS(443) 필수. 설정은 /etc/httpd/conf/httpd.conf(root, 오타 하나면 restart 실패),

httpd 설치 → start → 포트포워딩 → enable

Apache 데몬명은 httpd(apache로는 설치 안 됨). 설치만 되고 가동은 root가 systemctl start httpd.service. VirtualBox 80 → 80 포워딩 후 윈도우 IP로 테스트 페이지 확인, 부팅 자동 시작은 ntsysv 또는 systemctl enable. HTTP는 4xx(요청·설정)와 5xx(서버 = 인프라 책임) 대역으로 책임이 갈리고, 실무에서 가장 스트레스인 코드는 502·503·504.

DocumentRoot · 705 · DirectoryIndex · Copilot 웹 제작

환경설정은 /etc/httpd/conf/httpd.conf(root, 오타 하나면 restart 실패). 웹 접속자는 전부 게스트(others) → 홈 디렉토리 705. 경로가 없으면 데몬 기동 실패. DirectoryIndex는 왼쪽부터 순서대로 검사, 대문 = 랜딩 페이지. 호스팅 vs 클라우드

항목내용주의·이유
회사 구분호스팅 회사 = 카페24 등 / 클라우드 회사 = 네이버 클라우드(NCP), AWS, GCP, Azure, 메가존 등입사할 회사가 어느 쪽인지 정확히 알아야 함. 메가존클라우드도 서비스가 많아 서비스별 담당자가 따로 있음
네이버 클라우드 예AI(CLOVA, 네이버 자체 AI), Compute(Server, SSD Server, GPU Server, Bare Metal Server, Auto Scaling, Cloud Functions), Database(Cloud DB for MySQL / PostgreSQL / MSSQL / MongoDB / Cache, Serverless 등), 스토리지, 네트워킹, 보안 등DynamoDB는 AWS 전용 DB, GCP·NCP는 각자 다른 클라우드 DB 사용
차이호스팅과 클라우드는 완전히 다름. 웹호스팅은 클라우드(IaaS/PaaS) 안에 장착되는 더 작은 단위웹호스팅을 받는다고 클라우드가 되는 것은 아님 (그냥 호스팅)
용어웹호스팅, DB호스팅, 스트림 호스팅(실시간 영상 송출, 스트리밍)
웹클라우드보통은 그냥 클라우드 서비스라고 부름. 웹호스팅과 대비해 퍼블릭 클라우드(EC2 등 IaaS, PaaS)를 편의상 웹클라우드로 외우면 됨
실수 사례사수에게 호스팅이라고만 전하면 웹호스팅으로 받아들임클라우드 작업 중이면 혼선이 생기므로 용어를 정확히 구분
호스팅 ≠ 클라우드 — 웹호스팅은 클라우드(IaaS/PaaS) 안에 장착되는 더 작은 단위. 웹호스팅을 받는다고 클라우드가 되는 것이 아님

항목내용주의·이유
포트HTTP = 80, HTTPS = 44380번이 이미 다른 서비스로 돌고 있으면 충돌 (같은 포트에 서비스를 또 올릴 수 없음)
443 단독Listen은 열 포트를 지정하는 지시자라 80 없이 443만 여는 설정도 가능기본 베이스는 80이고 그 위에 환경설정·인증서를 해야 443이 돌아감
HTTPS 필요결제 시스템, 회원가입, 로그인 등 개인정보를 받는 사이트
HTTPS 불필요단순 홍보 사이트(공지, 상품 소개, 대표 인사말, 연혁, 조직도, 찾아오는 길, R&D, IR), 회원 전용이 아닌 누구나 쓰는 게시판
모니터링담당자가 신규 도메인 목록 등을 받아 접속해 HTTPS 여부 확인개인정보 입력이 있으면 신고 대상
요청 대응사이트 인프라 제작 요청을 받으면 회원가입·로그인이 있는지 묻고, 있으면 HTTPS도 준비해야 한다고 꼭 안내법 관련 자료는 인터넷진흥원 사이트에서 확인 가능
🔍 직접 확인 · 9강 80 없이 443만 여는 설정

Apache Lounge 포럼 답변이 Listen 80을 주석 처리하는 방법을 안내함 (공식 문서로는 확인 못 함). 강사는 "443만 돌리고 80은 안 돌리는 경우는 없다"고 설명

대역별 책임

대역책임설명
3xx개발자(백엔드) 쪽에서 확인리다이렉션 응답이라 오류 분류는 아니고, 인프라는 거의 신경 쓰지 않음. 주로 Node.js, Spring/Spring Boot 같은 백엔드 문제 → 브라우저 개발자도구(F12) → Network 탭에서 확인
4xx개발자·인프라 둘 다 확인요청이 맞는지 틀린지 살펴서 따짐
5xx인프라 담당자뜨면 일단 인프라 책임 → 바로 사과. 소스코드를 보는 개발자에게 떠넘기기 불가

웹 환경 문제가 터질 때 나오는 코드가 HTTP 상태 코드이고, 이 코드로 책임 소재를 따지는 경우가 많음 (책임 구분은 현장 관행이고 표준 규정은 아님). 300번대는 신경 쓰지 말고 400·500번대 위주로 구분, 전부 외울 필요는 없음

코드별 의미

코드의미상황·메모
401인증 필요로그인·토큰이 없어 인증이 안 된 상태. 접근 권한 없음(permission)은 403으로 구분
402요금 제한(Payment)유료 API 서비스에서 요금 미납 등으로 걸리는 경우가 있고 자기 서버 문제가 아님. API 서버 구축(환율·실시간 정보 API)을 요청받으면 알아야 함. 표준 관례가 거의 없는 코드이며 요청 횟수·요금 제한은 429 Too Many Requests가 일반적
403승인 거부·접근 금지관리자(최고 관리자) 페이지를 특정 IP 외 접근 못 하게 막을 때 뜸, 페이지 자체가 안 열림
404경로·파일 없음웹 서버에 없는 파일 요청 (예: index2.html을 만들지 않았을 때)
405메소드 허용 안 됨 (GET·POST 등)가장 걸리면 괴로운 코드, 서버에서 GET·POST 통신을 허용했는지 확인
406콘텐츠 협상 실패요청 조건(Accept 등)에 맞는 콘텐츠가 없을 때의 응답. JSON 형식을 허용하지 않는 경우로 설명되지만 JSON 허용 설정과 직접 관계는 없음. 일반 웹 서비스에서는 거의 안 뜨고 단독 DB 서버·CDN 서버에서 주로 발생
500서버 내부 오류뜨면 인프라 책임, 사과
501메소드 인식 불가 (Ajax 메소드)서버가 요청 메소드를 지원하지 않을 때(GET·HEAD 외 구현 안 됨). 개발자가 구현한 Ajax 요청 방식(POST·GET 외 UPDATE·PATCH 등)을 서버가 인식 못 하는 경우, 포트를 안 열어서 나는 코드는 아님
502게이트웨이 불량중간 서버 문제 — 로드 밸런서 사용 시 WAS와 잘못 연결됐을 때 많이 발생, 웹 서비스(nginx·아파치)에서 걸림
503서비스 불능콜이 안 나가는 비상사태로 보는 코드. 점검·과부하 등으로 서버가 일시적으로 요청을 처리할 준비가 안 된 상태이고 Retry-After 헤더를 쓸 수 있음
504게이트웨이 지연(시간 초과)백엔드에서 DB를 무겁게 돌리거나 로드가 너무 많을 때. 로그로 원인 규명 — 개발자 코드의 무한 루프(CPU 100%)면 개발자 책임, 아니면 워커 서버(마스터-워커 구조)가 응답을 못 한 것 → 워커 쪽 점검
505HTTP 버전 문제(프로토콜)요청의 HTTP 버전을 서버가 지원하지 않을 때의 응답 — 세부로는 HTTP/2·HTTP/3 버전 문제
506-거의 볼 일 없음, 신경 안 써도 됨

public_html 유지 시기본 public_html을 그대로 쓰면 사용자는 public_html 안에 HTML·CSS·JavaScript를 넣어야 웹이 뜸메인 사이트의 html과 이름이 달라 관리가 헷갈림 → html로 통일

403 Forbidden 해결

# 증상 : ~korea 접속 시 Permission denied / Forbidden

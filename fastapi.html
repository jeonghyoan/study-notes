FastAPI 통합 학습노트

FastAPI 통합 학습노트 · 범위: API 개념(HTTP 메서드 GET·POST·PUT·DELETE → 백엔드 DB 처리 → JSON/XML 응답) → 뷰 테이블(가상 테이블·Materialized View) → 응답 형식 JSON·XML·CSV → REST·RESTful·FastAPI 정의와 프레임워크 계보 → 활용 3분야(모델 서빙·클러스터 브리지·파이프라인 대시보드) → pip3 설치(fastapi·uvicorn·nest_asyncio, 마스터·워커) → 기본 코드(앱 객체·데코레이터·경로 파라미터) → Jupyter 가동(uvicorn.Config·Server·asyncio.create_task) → .py 파일 가동(uvicorn main:app --host --port·reload) → 경로 파라미터 접근 제어. 연결 파일: spark.html(PySpark·JupyterLab·마스터 포트), mysql.html(조회·뷰), was.html(Java WAS와 API 서버의 차이)

GET · POST · PUT · DELETE

API는 통신 창구 — 요청 4개를 받아 백엔드가 DB를 조회하고 JSON·XML로 돌려줌. 응답을 받으려면 포트가 열려 있어야 하고, 포트 충돌이 나면 기동 실패. 개방은 인프라 담당자와 협의 (1·3장)

uvicorn main:app

실행은 uvicorn, 인자는 파일명:변수명. --host 마스터 IP --port 9999, 배포는 --workers N. Jupyter 가동은 nest_asyncio가 필요하고 .py 파일 실행이 정석 (5·7·8장)

9999 LISTEN · 200 OK

netstat -lntpu에 9999 LISTEN·프로세스 python이 보이면 가동. 로그의 Uvicorn running on ...·200 OK가 정상 신호. 파일 이름 fastapi.py는 금지 (6·8장)

한눈에 보기 — 요청 4개를 받아 JSON·XML로 돌려주는 창구

① 클라이언트 요청

GET · POST · PUT · DELETE

포트

② 백엔드 처리

DB 쿼리 · 조건 확인

③ 응답

JSON · XML

④ 창구 유지

포트 개방 · 키 발급

API는 정의 암기보다 통신으로 이해 — 요청이 들어오면 백엔드가 DB를 조회해 결과를 돌려주고, 그 창구는 포트로 열려 있음

정의와 동작

항목내용주의·이유
정의API = Application Programming Interface — 프로그램끼리 값을 주고받는 창구정의를 외우는 문제는 나오지 않음 — 통신으로 이해
요청 규약HTTP 요청 통신 규약 GET·POST·PUT·DELETE (+ PATCH 등)이 4가지만 알면 됨
처리요청을 보내면 백엔드가 DB 쿼리 등으로 처리 → 결과(JSON/XML)를 돌려줌응답 형식은 2장
만드는 이유영화진흥위원회가 외부에 자기 DB(MySQL) 접근을 열어 줄 수는 없음 → DB 값을 가져와 JSON으로 뿌려 주는 창구를 만든 것API 사용자는 테이블 구조·계정을 몰라도 값만 받음
CSV 제공처XML/JSON 생성이 번거로워 DB를 엑셀(CSV)로 올려 둔 경우요즘 API는 JSON/XML이 기본 — 형식 비교 2장
포트API 서버도 포트를 열어야 외부에서 접근 가능개방은 인프라 담당자와 협의가 필요한 일 — 3장

메서드 4개 — 같은 동작의 SQL 대응

메서드역할대응하는 SQL
GET값을 조회해 가져옴SELECT
POST값을 보내 새로 등록INSERT
PUT값을 보내 수정UPDATE
DELETE값을 지정해 삭제DELETE

표준 예시 — 메서드와 SQL의 대응은 HTTP·SQL 표준 관례를 정리한 것. 브라우저 주소창으로 테스트할 수 있는 것은 GET뿐이고, POST는 폼에서 값이 넘어와야 함 (9장).

응답 값의 출처 — 베이스 테이블과 뷰 테이블

구분내용주의·이유
베이스 테이블실제 데이터를 저장하는 일반 테이블데이터가 디스크에 있는 실체
뷰 테이블가상 테이블 — 데이터를 디스크에 따로 저장하지 않고, 복잡한 JOIN 쿼리를 간단히 호출하게 만든 것API가 조인 결과를 짧은 쿼리로 꺼내는 통로
장점긴 조인문을 한 번에 호출하고 원하는 컬럼만 출력호출하는 쪽 쿼리가 짧아져 실수·노출이 줄어듦
속도일반 뷰는 쿼리문을 저장해 둔 가상 테이블이라 호출할 때마다 원본 쿼리가 실행됨 → 속도 이점이 있는 구조가 아님목적은 편의·보안·재사용. 결과까지 저장해 빠르게 조회하는 것은 Materialized View — MySQL 8.0 Reference Manual(CREATE VIEW)
-- [마스터 · MySQL 프롬프트 · hong]
-- 회원·포인트 테이블을 매번 길게 조인하는 대신 뷰로 묶어 짧게 호출 — API가 이 결과를 JSON으로 뿌림
SELECT a.mid, a.user, b.money FROM member a JOIN point b WHERE a.mid = b.mid;
  • 조회·뷰 실습
    SELECT 문법과 테이블 조회: mysql.html 9장
  • 뷰와 API 응답
    이 파일 9장 — 조회 결과를 반환 자리에 넣는 방식
API = 통신 — 요청 규약은 GET·POST·PUT·DELETE 4개. 요청을 받은 백엔드가 DB를 조회해 JSON/XML로 응답하고, 그 창구는 포트로 열려 있음. 뷰는 속도를 위한 저장이 아니라 조인문을 묶어 두는 편의 장치 — 결과 저장은 Materialized View

응답 형식 — JSON·XML·CSV

① XML

  • 태그 이름을 직접 정함
  • SGML 파생

② JSON

  • AI가 선호
  • 객체 + 배열

엑셀 표 · 쉼표 구분

  • XML/JSON 만들기 번거로울 때
  • 갱신 불가

요즘 API의 기본 응답은 JSON·XML — 같은 데이터를 태그로 감싸면 XML, 중괄호·대괄호로 묶으면 JSON

XML과 JSON 비교

구분XMLJSON
형태태그로 데이터 표현key-value 배열/객체 형태
만드는 법태그 이름을 자기가 정함 (보통 테이블 컬럼명으로)중괄호 · 대괄호 중첩
AI 선호JSON을 더 선호
같은 값의 예<color>blue</color>{"color": "blue"} (표준 예시)

XML — 태그를 직접 만들면 끝

<!-- [마스터 · /home/spark/color.xml 파일 안 · spark] -->
<!-- 태그 이름을 자기가 정함 — 보통 DB 테이블의 컬럼명과 같게 맞춤 -->
<color>blue</color>
<food>삼겹살</food>
<fruit>peach</fruit>
<country>korea</country>
<!-- 태그를 한 줄에 이어 붙여도 같은 형식 -->
<이름>홍길동</이름><나이>35</나이>
  • 행 늘리기
    같은 태그 묶음을 반복하면 여러 행 — 컬럼명을 태그로 두면 표와 1:1 대응
  • 계보
    XML = SGML에서 파생된 마크업 언어. HTML도 SGML 계열이며 XML이 HTML에서 나온 것이 아님 — W3C XML 1.0 스펙
  • JSON 구조
    JSON은 객체(key-value)와 배열로 이루어진 데이터 형식 — 배열만 있는 형식이 아님. RFC 8259(ECMA-404)

CSV — 표를 그대로 올린 형식

  • 쓰는 곳
    XML/JSON 생성이 번거로운 제공처가 DB를 엑셀(CSV)로 올려 둔 경우
  • 한계
    행을 고치거나 지우는 갱신이 안 되는 일방향 형식 — API 응답으로 쓰기엔 JSON/XML이 기본
  • 공공데이터
    영화진흥위원회처럼 API로 JSON을 주는 곳은 키를 받아 호출 — 키 사용 예는 9장, 호출 실습은 spark.html 18장
데이터 형식 — JSON은 AI가 선호하고 객체 + 배열 구조(RFC 8259), XML은 태그로 표현하며 태그 이름은 보통 컬럼명, SGML 파생. CSV는 XML/JSON 생성이 번거로울 때 쓰는 표 형식으로 갱신 불가

REST와 RESTful

항목내용주의·이유
면접 단골REST / RESTful API를 구축할 때 포트를 어떻게 여는지원칙 설명만 하고 포트·인프라 협의를 빼면 답이 반쪽
REST API웹에 존재하는 자원을 주소(URI)로 지정해 가져오는 아키텍처 스타일특정 라이브러리·제품 이름이 아니라 설계 원칙
표현 방식 두 가지abc.co.kr/bbb.html?key=API키(쿼리 파라미터 — 영화진흥위원회 방식) / abc.co.kr/bbb/키값(경로에 값)둘 다 자원을 주소로 가리키는 방식 — 이 차이로 REST와 RESTful이 갈리지 않음
RESTfulREST 원칙(자원 URI · HTTP 메서드 · 무상태 등)을 지킨 API를 가리키는 말Roy Fielding 박사 논문(2000) — 쿼리 파라미터 사용 여부가 기준이 아님
포트REST든 RESTful이든 서버가 뜨려면 포트를 열어야 함인프라 담당자와 협의가 필요한 일 — 자기 마음대로 열 수 없음

FastAPI의 자리

항목내용주의·이유
정의파이썬으로 REST API 서버를 빠르게 구축하는 프레임워크"Fast"는 말 그대로 빠르다는 뜻
언어파이썬 전용자바·닷넷 쪽에서는 FastAPI를 거의 못 씀. Node.js 등 다른 언어로도 API 서버 구축은 가능
자바 계보자바 웹 프레임워크 → Spring → Spring Boot같은 역할을 자바에서 하는 조합
파이썬 계보Django(대표 기본 프레임워크) · Flask(예전에 많이 씀) · FastAPIDjango·Flask를 먼저 배운 사람이 FastAPI로 오는 흐름
다음 단계MLOps는 이후에 다룸 — 이 앞 단계인 API 상식을 알아야 연결됨핵심 조합은 FastAPI + Spark (Spark: spark.html 1~2장)
REST·RESTful 구분 — REST는 자원을 URI로 가져오는 아키텍처 스타일, RESTful은 그 원칙(URI·메서드·무상태)을 지킨 API. 쿼리 파라미터를 쓰는지로 갈리지 않음. 면접에서는 두 용어에 더해 포트 개방·인프라 협의까지 답해야 완성
FastAPI의 자리 — 파이썬 전용 프레임워크(자바·닷넷에서는 거의 못 씀). 같은 역할의 자바 계보는 Spring → Spring Boot, 파이썬은 Django·Flask 이후 FastAPI. 이 환경의 핵심 조합은 FastAPI + Spark

데이터 파이프라인 모니터링·제어 대시보드 백엔드PySpark 배치 작업 상태 확인, 수집 로그·업로드 파일을 관리하는 관리자 웹 인터페이스의 REST API운영 화면의 뒤에서 도는 API — 배치 실패를 사람이 빨리 봄
활용 3분야 — ① 실시간 모델 서빙(MLlib·PySpark) ② 분산 클러스터와 외부를 잇는 브리지(Spark 결과·파일 접근 창구) ③ 파이프라인 모니터링·제어 대시보드의 REST API 백엔드

# [마스터 · /home/spark/test_api.py 파일 안 · spark]
#!/usr/bin/env python3
from fastapi import FastAPI
# 주피터에서 실행할 때만 필요한 import — .py로 돌릴 때는 uvicorn만 사용 (7·8장)
import asyncio, nest_asyncio, uvicorn

# 기본 엔진 — 클래스를 불러 app 변수에 넣음. 라우트는 이 객체에 붙임
app = FastAPI()

# 데코레이터(@ = annotation) : GET 메서드 + URI "/" 등록 → 루트 주소 요청을 이 함수가 처리
@app.get("/")
def read_root():
    # dict를 돌려주면 FastAPI가 JSON으로 변환 — {"msg": "..."} 형태가 그대로 응답
    return {"msg": "서버 오픈되었습니다"}

# 경로에 파라미터 id — /data/홍 처럼 주소 끝의 값을 함수 인자로 받음
@app.get("/data/{id}")
def read_item(id: str):                  # int=숫자만, str=문자
    # 받은 값을 키 두 개로 돌려줌 — f-string으로 문장 안에 값 삽입
    return {"값": id, "데이터 출력": f"데이터 값은 {id}"}

# [마스터 · JupyterLab 노트북 셀 · spark]
import nest_asyncio, asyncio, uvicorn
nest_asyncio.apply()                     # 이미 도는 이벤트 루프에 중첩 허용 — 비동기 충돌 해결

# app 객체를 직접 전달 — "모듈명:app" 문자열 대신이라 주피터에서 모듈을 찾지 못하는 문제가 없음
config = uvicorn.Config(app, host="0.0.0.0", port=9999, log_level="info")
server = uvicorn.Server(config)
asyncio.create_task(server.serve())      # 비동기 서버를 task로 등록 — 셀이 끝나도 서버가 계속 돎
print("FastAPI 서버가 background로 구동되었습니다.")
  • 서버 두 종류
    서버는 동기·비동기 두 종류이고, 여기서는 비동기 서버를 task로 등록
  • 정상 신호
    로그의 빨간 글씨가 전부 에러는 아님 — Uvicorn running on ...이 보이면 정상, 200 OK가 찍히면 통신이 정확히 된 것
  • 종료
    주피터 Kernel Shutdown을 누르면 서버가 죽고 포트가 끊김 — 새로고침하면 접속 불가
주피터 가동 — 이벤트 루프가 이미 도는 환경이라 uvicorn.run()은 충돌. nest_asyncio.apply() + uvicorn.Config(app, ...) + uvicorn.Server + asyncio.create_task(server.serve())로 띄우고, 가동 전 기존 서버·앱을 kill해 포트 충돌을 없앰

API 키를 경로로 받아 if로 거르는 최소한의 접근 제어 — 영화진흥위원회 API의 키 검사와 같은 구조

# [마스터 · /home/spark/main.py 파일 안 · spark]
# 경로 파라미터 id — 브라우저에서 /login/값 으로 호출
@app.get("/login/{id}")
def login(id: str):
    # 허락한 ID만 통과 — 키 검사에 해당하는 조건
    if id != "허락한아이디":
        return {"데이터": "유효하지 않은 API입니다"}   # 조건으로 접근 제한
    # 통과했을 때만 데이터 반환 — 키 : 값 형태
    return {"배열 출력": "aabbcc"}
  • key의 의미
    반환값의 key는 영화진흥위원회 JSON의 key와 같은 개념 — 값에 이름을 붙여 내보내는 역할
  • 접근 제어
    허락한 ID가 아니면 데이터를 안 내주는 식으로 if 접근 제어 가능
  • DB 연결
    이 값을 MySQL에서 끌어와 반환 자리에 부으면 영화진흥위원회처럼 배열이 쭉 나옴 — 조회: mysql.html 9장, 공공 API 적재·조회: spark.html 18~19장
  • POST 미검증
    POST는 지금 테스트 불가 — HTML 폼에서 값이 넘어와야 하기 때문. 이후 VS Code + 바이브 코딩(AI)으로 HTML을 만들어 테스트 예정
경로 파라미터 접근 제어 — /login/{id}로 받은 값을 if로 비교해 허락한 ID만 데이터를 돌려주는 구조가 API 키 검사의 최소형. GET만 브라우저로 테스트 가능하고 POST는 폼이 있어야 함
  • 관련 파일
    WAS(Tomcat)와 API 서버의 차이·포트 개방: was.html 1~2장 / Spark 마스터·워커 포트·Jupyter: spark.html 2·13장 / MySQL 조회·뷰: mysql.html 9장

@app.get("/") / @app.post(...) / @app.put(...) / @app.delete(...)데코레이터로 메서드·경로 등록. 함수가 돌려준 dict가 JSON 응답
@app.get("/data/{id}") → def read_item(id: str)경로 파라미터 — int=숫자만, str=문자. http://IP:포트/data/홍으로 확인
@app.get("/login/{id}") + if id != "허락한아이디": return {"데이터": "유효하지 않은 API입니다"}키 검사형 접근 제어 — 통과 시에만 {"배열 출력": "aabbcc"} 반환

nest_asyncio.apply()이미 도는 이벤트 루프에 중첩 허용 — uvicorn.run() 충돌 해결
config = uvicorn.Config(app, host="0.0.0.0", port=9999, log_level="info")모듈 문자열 대신 app 객체 직접 전달 — 주피터에서 모듈을 못 찾는 문제 회피
server = uvicorn.Server(config) / asyncio.create_task(server.serve())비동기 서버를 task로 등록 — 셀이 끝나도 background로 구동
chmod 750 /home/spark홈 디렉터리 권한 700 → 750 — 서버가 파일·모듈을 읽도록 그룹에 통과 허용
Kernel Shutdown서버가 죽고 포트가 끊김 — 새로고침하면 접속 불가

cd ~ / netstat -lntpumain.py가 있는 홈으로 이동, 실행 전 9999가 없는지 확인

python3 main.py실행부(__main__)로 직접 기동하는 대안 — 같은 uvicorn.run 설정 사용
오류·확인 (6~8장)
RuntimeError (이벤트 루프)동기 환경에서 비동기 코드 실행 시 발생 — nest_asyncio.apply()로 해결
모듈을 찾지 못함uvicorn.run("main:app")의 모듈명이 실제 파일·위치와 다를 때 — 객체 직접 전달 또는 홈에서 실행
Uvicorn running on http://0.0.0.0:9999가동 정상 신호 — 빨간 글씨가 전부 에러는 아님
200 OK통신이 정확히 된 상태 — 브라우저에 JSON 출력
localhost:9999 접속 거부서버가 죽었거나(창 닫음·Ctrl+C·Kernel Shutdown) 포트를 못 잡음 — 프로세스·포트 확인
SELinux · 방화벽포트가 열려도 화면이 안 뜨는 원인 — 수업 환경은 off, 실서버는 개방 정책 확인

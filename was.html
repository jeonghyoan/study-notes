WAS(Tomcat) 통합 학습노트

WAS 통합 학습노트 · 범위: 호스트 리눅스 VM에서 Tomcat(WAS) 직접 세팅(Core tar.gz 설치 · server.xml 포트 8005·8080·8443 · web.xml 첫 화면 · Java 설치 · 가동·정지·포트 확인) → Java 버전별 Tomcat 컨테이너 구성 → root는 설치만, 일반 사용자로 Tomcat 설치·기동 → 여러 Java 버전 설치 후 update-alternatives로 전환. 컨테이너·Compose 기본: docker.html 4·5장, nginx 프록시로 80 연결: nginx.html 6장, HTTP 502·503·504: httpd.html 10장

Java ↔ Tomcat 버전

Tomcat 8.5는 Java 7 이상, 10.1은 Java 11 이상, Spring Boot 3.x는 Java 17 이상 → 조합을 맞춰 컨테이너 구성 (7장)

root 설치 · mz 실행

Java·wget은 root로 설치, Tomcat 압축 해제·기동은 일반 사용자(mz, 호스트 VM에서는 apink) → root는 설치 때만 (8·1장)

update-alternatives

버전 변경 요청마다 RPM을 지우지 말고 여러 버전을 설치해 두고 --config java로 선택 전환 (9장)

WAS 역할과 설치 주체

항목내용주의·이유
구축 요청개발자가 "도메인 치고 8080 치면 이상하다, 연결해 달라"고 요청하는 경우가 있어 WAS 구축 → nginx 결합 필요프록시 연결은 nginx.html 6장
WAS ≠ 웹 서버WAS는 웹 서버와 다른 계층패키지명·확장자로 구분 (httpd.html 1장)
설치 주체WAS는 root가 아니라 일반 사용자(apink)에게 설치·세팅root가 관리하면 모든 WAS 포트를 root가 관리해야 해서 힘듦
root가 관리하면일반 사용자는 정지도 못 하고 계속 root에게 요청해야 함개발자가 직접 재배포·정지를 해야 하는 일이 잦음
실무회사에서도 세팅 비용을 받고 해 주고, WAS 세팅 후 FTP를 열어 주면 개발자가 알아서 파일을 업로드인프라는 포트·환경만 열어 주는 역할

내려받기·압축 해제 (apink)

# [호스트 리눅스 · root]
# Tomcat을 설치·실행할 일반 사용자로 전환
su apink

# [호스트 리눅스 · apink]
# 작업 위치 확인 (pwd) — 홈에서 받아야 소유자가 apink
cd /home/apink
# 브라우저에서 복사한 tar.gz 링크를 Shift+Insert로 붙여넣기 → apache-tomcat-10.1.61.tar.gz
wget <복사한 tar.gz 링크>
# 받은 파일 확인
ls -al
# 압축 해제 — root가 아니라 apink가 수행
tar xf apache-tomcat-10.1.61.tar.gz
# 버전이 붙은 디렉토리명을 tomcat으로 변경 (끝에 / 붙이지 말 것)
mv apache-tomcat-10.1.61 tomcat

버전 선택Apache Tomcat 사이트에서 개발자가 요청한 버전으로 받음(9·10 등) → 이번에는 10현재 지원 버전은 11.0·10.1·9.0이고 8.5는 2024-03-31 지원 종료(EOL)

이 단계프록시를 잡지 않고 IP:8080으로 바로 Tomcat 화면을 띄움프록시는 nginx.html 6장

한눈에 보기 — 포트 3개를 외운다

리다이렉트(HTTPS·SSL)

사용자가 여러 명이면 세 포트를 모두 겹치지 않게 배정

주요 라인

# [호스트 리눅스 · apink]
# WAS 환경설정 파일 편집 (vi 안에서 :set number 로 줄 번호 표시)
vi /home/apink/tomcat/conf/server.xml
줄설정의미
22<Server port="8005" shutdown="SHUTDOWN">셧다운(정지) 포트 8005
60Executor … maxThreads="150" minSpareThreads="4"Thread Pool
70~74<Connector port="8080" protocol="HTTP/1.1" connectionTimeout="20000" redirectPort="8443" />서비스 포트 8080 (클라이언트 접속 포트, 웹 접속 시 IP:8080), 리다이렉트 포트 8443
75~<!-- <Connector executor="tomcatThreadPool" port="8080" … redirectPort="8443" /> -->Thread Pool 사용 Connector (주석 처리됨)
143~144<Host name="localhost" appBase="webapps" unpackWARs="true" autoDeploy="true">개발자가 건드리는 영역
포트역할주의·이유
8005셧다운(정지) 포트 — 정지시킬 때 쓰는 포트서비스 포트와 구분해서 외울 것
8080서비스(가동) 포트 — 클라이언트가 접속하는 포트웹 브라우저에서 IP:8080
8443리다이렉트 포트 = 443(HTTPS) 앞에 8을 붙인 것HTTPS·SSL 포트로 공용이라 거의 바꾸지 않음 (강사가 "843번"이라 말한 것은 8443의 말실수)

이 화면 server.xml에서 확인되는 포트는 셧다운 8005, HTTP 8080, redirectPort 8443 세 개 — AJP 포트는 화면에 나오지 않고, AJP를 쓸 때는 secret 설정이 필수

셧다운 포트 8005 중복

항목내용주의·이유
정지가 필요한 이유개발자가 정지 후 재배포하는 경우가 있음가동·정지 권한을 일반 사용자에게 주는 이유
포트가 겹치면같은 포트에는 하나의 프로그램만 대기할 수 있어 나중에 뜨는 인스턴스가 기동 충돌을 일으킴다른 WAS까지 함께 종료되지는 않음
정지가 안 될 때kill로 강제 종료하는 상황이 생김포트가 겹친 상태에서는 정지 명령이 엉뚱한 곳으로 갈 수 있음
여러 인스턴스한 호스트에서 여러 인스턴스를 띄울 때는 포트를 겹치지 않게 하거나 portOffset 사용포트 배정은 엑셀로 정리해 둠 — 포트를 잘못 배정한 사업 단위 사고 사례가 있을 정도로 중요

포트 배정 (사용자 여러 명)

사용자(WAS)가 여러 명이면 세 포트를 각각 다음 번호로 증가시켜 겹치지 않게 배정. 다음 번호도 이미 사용 중이면 또 다른 번호로 배정 (예: 메가존 사용자 추가 시)

Thread Pool·Host 구간

항목내용주의·이유
주석 문법<!-- -->는 #이 아닌 XML 방식 주석XML 파일이라 # 주석은 동작하지 않음
Executor여러 Connector가 함께 쓸 수 있는 공유 스레드 풀 — 주석을 푼 Connector가 executor="tomcatThreadPool"로 그 풀을 사용풀이 가득 찼을 때만 동작하는 구조가 아님
누가 쓰나개발자가 쓴다고 하면 개발자가 주석을 풀어 사용 → 서버 담당자는 손대지 않음Thread Pool 설정은 애플리케이션 특성에 달림
포트 변경 시8080을 다른 번호(예: 8082)로 바꿀 때는 위 Connector와 아래 주석 상태 Connector의 포트를 같은 번호로 바꿔 둠개발자가 주석을 풀면 그 포트로 동작
Host 영역143~144번 Host(webapps 패키지 등)는 개발자가 자기 문법으로 설정서버 담당자는 몰라도 됨
이번 실습8080 그대로, server.xml은 수정하지 않고 저장·종료포트 변경 시연은 나중에
Tomcat 포트 — 셧다운 8005(22번 줄) · 서비스 8080(Connector 70번 줄) · 리다이렉트 8443. 사용자가 여러 명이면 세 포트를 각각 증가시켜 겹치지 않게 배정, 겹치면 나중 인스턴스가 기동 충돌

root가 가동한 경우 (소유자 문제)

항목내용주의·이유
실행 결과root가 /home/apink/tomcat/bin/에서 ./startup.sh → Tomcat 화면 정상, 이후 apink가 ./shutdown.sh → 정지도 됨압축을 apink가 풀어 bin 안 파일 소유자가 전부 apink apink(startup.sh는 rwxr-x---)
root 소유가 되면startup.sh·shutdown.sh의 소유자·그룹이 root가 되면 apink는 실행·정지에 제약을 받음shutdown.sh는 server.xml의 셧다운 포트(8005)로 종료 명령을 보내 정지시키는 방식이라 소유자만으로 정지 가능 여부가 갈리지는 않음
원칙WAS는 일반 사용자가 설치·핸들링, root로 실행하지 않음root 실행 시 생성 파일이 root 소유가 되어 개발자가 손댈 수 없게 됨
가동·정지 — tomcat/bin에서 ./startup.sh·./shutdown.sh, 일반 사용자가 수행. 접속은 IP:8080에서 Apache Tomcat 화면, 8080·8005가 LISTEN이면 정상. 웹과 WAS는 별개로 운영 가능

# [was11 컨테이너 · root]
# 설치된 Java 확인 → 미설치면 java: command not found
java -version
# 이 컨테이너에는 Java 11 설치
dnf install java-11
# Tomcat을 설치할 일반 사용자 생성 (passwd는 생략)
useradd mz
# 표준 예시: 홈 디렉터리 권한을 확인할 위치로 이동
cd /home
# /home인지 확인한 뒤 상대 경로 mz 사용
pwd
# useradd 직후 홈 디렉터리 기본 권한은 700 → mz가 drwx------(700)이면 조정 대상
ls -al
# 홈 디렉터리 접근 권한을 필요한 수준(755)으로 변경 (더 넓은 권한은 불필요)
chmod 755 mz
# 다운로드 도구는 root에서 설치
dnf install wget
# Tomcat 설치·실행 사용자로 전환
su mz
# [was11 컨테이너 · mz]
# Tomcat 작업 위치 확인 → 잘못된 경로에서 실행하면 파일을 못 찾거나 엉뚱한 위치에 설치
pwd
# Tomcat 소스가 아닌 바이너리 tar.gz 다운로드 (브라우저에서 복사한 링크)

# Tomcat 기동 → 브라우저 리눅스IP:9800에서 Tomcat 화면

# [was11 또는 was17 컨테이너 · root]
# 설치된 Java 중 사용할 버전 선택 (번호 입력, Enter는 현재 유지)
update-alternatives --config java
# 선택 변경 확인
java -version
🔍 확인 필요 · Java 17과 상세 화면

"DB 연결 등 상세 화면이 Java 17에서 안 뜬다"는 내용은 자료에서 미확정으로 표시됨 → 임의로 확정하지 않음

Java 버전 전환 — 버전 변경 요청마다 RPM을 지우지 말고 여러 버전 설치 후 update-alternatives --config java로 전환. *+가 현재 선택, 번호 입력으로 변경 → java -version으로 확인

통합 명령어 치트시트

영역별 모음. Docker·Compose 명령은 호스트 root, Tomcat 설치·가동은 호스트 리눅스의 일반 사용자 apink(컨테이너 실습은 mz), Java 설치만 root.

명령어기능 및 핵심 메모
설치·포트 점검
su apink / cd /home/apinkWAS를 설치·실행할 일반 사용자 전환과 홈 이동
tar xf apache-tomcat-10.1.61.tar.gz / mv apache-tomcat-10.1.61 tomcatCore tar.gz 압축 해제와 디렉터리명 단축(끝에 / 없이)
vi /home/apink/tomcat/conf/server.xml포트 설정 확인 — 22번 8005, 70번 8080, redirectPort 8443
vi /home/apink/tomcat/conf/web.xml맨 아래(약 4777행) welcome-file-list 첫 화면 순서 확인
netstat -ln | grep 8080 / netstat -ln | grep 8005가동 후 LISTEN 확인, 정지 상태면 아무것도 안 나옴
kill정지가 안 되는 WAS 프로세스 강제 종료 — 포트가 겹친 상태에서 사용
컨테이너
vi hosting.yamlCompose 파일 생성·편집, 복사한 설정은 Shift+Insert로 붙여넣기
docker compose -f hosting.yaml up -d지정 파일의 서비스로 WAS 컨테이너 생성·실행, version 속성 obsolete 경고는 무시 가능
docker ps / docker compose ps컨테이너·포트 확인: was11은 9800, was17은 9801
docker exec -it was11 /bin/bash / docker exec -it was17 /bin/bash대상 WAS 컨테이너 접속, 11번·17번 컨테이너 혼동 주의
Java·Tomcat
java -versionJava 버전 확인, 미설치면 command not found
dnf install java-11 / dnf install java-17각 컨테이너에 대응 Java 설치: was11에는 11, was17에는 17
useradd mz / ls -al / chmod 755 mz일반 사용자 생성·권한 확인·홈 디렉터리 권한 조정 (mz가 700일 때 변경)
su mz / pwdTomcat 설치 사용자로 전환 / 작업 경로 확인, root는 설치 때만
dnf install wget / wget <링크>root에서 다운로드 도구 설치 / 브라우저에서 복사한 Tomcat 바이너리 링크 다운로드
tar xfz apache-tomcat-*.tar.gzTomcat 바이너리 압축 해제, tar.gz 원본 보존
mv apache-tomcat-* tomcat버전이 붙은 Tomcat 디렉터리명을 tomcat으로 단축
./startup.sh / ./shutdown.shbin 디렉터리에서 Tomcat 기동·종료, 종료 스크립트는 stop.sh가 아님
update-alternatives --config java / java -versionroot에서 설치된 Java 버전 선택 / 변경 결과 확인
dnf install java* / dnf install java-17*설치 가능한 버전 목록(1.8·11·17·21·25) 확인 / Java 17 패키지 18개 전체 설치(root)

PostgreSQL 통합 학습노트 · 범위: 공식 이미지 컨테이너 실행·이름 있는 볼륨 → psql 접속·pg_hba.conf 인증 → postgresql.conf 메모리·로그 설정과 재시작 검증 → 로컬 서버의 설치·버전 선택(dnf module)·초기화·pg_hba 접속 허용·postgresql.conf 수신 주소와 psql 로컬 접속(peer 인증). Docker·Compose 기본 명령은 docker.html 4·5장

pgdata 볼륨

데이터 경로 /var/lib/postgresql/data를 이름 있는 볼륨에 연결 → 컨테이너를 바꿔도 데이터 유지 (1장)

pg_hba 첫 일치

규칙은 위에서부터 먼저 맞는 줄 적용. trust는 비밀번호 검증 없음 → md5/scram-sha-256으로 (2장)

cp → 수정 → restart

컨테이너에 편집기가 없으면 docker cp로 꺼내 호스트에서 수정 → 되돌리고 docker restart → 로그·접속으로 검증 (3장). 로컬 서버는 postgresql:16 스트림 → --initdb → 0.0.0.0/0 md5 + listen_addresses (4~6장)

공식 이미지·이름 있는 볼륨과 컨테이너 실행

한눈에 보기 — 이미지에서 볼륨 보존 컨테이너까지

① 이미지

postgres:14.24 · df -m

② 볼륨

docker volume create pgdata

③ docker run

-e POSTGRES_PASSWORD · -p 5432:5432

④ Compose 이전

volumes: external: true

항목내용
이미지
  • Docker Hub에서 Official Image로 표시된 postgres 확인 → 태그 14.24 사용
  • 태그 접미사 없는 기본 이미지도 Debian 기반일 수 있음. trixie = Debian 13 코드명 (Ubuntu·CentOS 계열 아님)
용량다운로드 전 df -m으로 디스크 여유 확인. 화면의 postgres:14.24 크기 약 624MB
슈퍼유저MariaDB의 root 대신 postgres
환경변수·포트·경로POSTGRES_PASSWORD = 초기 비밀번호 설정용 / 기본 포트 5432 / 데이터 경로 /var/lib/postgresql/data
이름 있는 볼륨pgdata 볼륨에 저장 → 컨테이너 교체와 데이터 생명주기 분리. 비밀번호 a1234는 연습값
docker run에서 먼저 확인
  • Compose로 옮기기 전에 같은 이미지·환경변수·포트·볼륨으로 직접 실행해 정상 기동 확인
  • 이미 초기화한 실습 데이터가 있으면 볼륨 경로와 재사용 대상 확인
  • 외부 볼륨으로 선언하면 pgdata가 미리 존재해야 함
# [호스트 리눅스 · root]
# 호스트 여유 공간(MB) 확인 후 공식 이미지 다운로드
df -m
docker pull postgres:14.24
docker images
# 이름 있는 볼륨 생성 → DB 파일을 컨테이너 밖에 보존
docker volume create pgdata
# -e 초기 비밀번호(연습값) / -v 볼륨:데이터경로 / -p 호스트:컨테이너 / -d 백그라운드
docker run --name rds_psql -e POSTGRES_PASSWORD=a1234 \
  -v pgdata:/var/lib/postgresql/data -p 5432:5432 -d postgres:14.24
docker ps

# [호스트 리눅스 · /root/yaml/compose.yaml 파일 안]
services:
  # 서비스 키 (compose 명령 인자로 쓰는 이름)
  postgres:
    # docker ps에 보이는 고정 컨테이너 이름
    container_name: rds_psql
    image: postgres:14.24
    # 초기 슈퍼유저(postgres) 비밀번호. a1234는 연습값
    environment:
      - POSTGRES_PASSWORD=a1234
    # 이름 있는 볼륨 pgdata → PGDATA 경로
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"
volumes:
  pgdata:
    # 이미 만든 볼륨을 사용 → Compose가 생성·삭제하지 않음 (down -v로도 안 지워짐)
    external: true
    name: pgdata
볼륨과 데이터 보존 — 컨테이너 안에만 저장한 데이터는 컨테이너 삭제와 함께 소멸, 이름 있는 볼륨은 유지. external 볼륨은 미리 만들어 둬야 하고 Compose가 지우지 않음 (Compose 생명주기: docker.html 5장)

psql 접속과 pg_hba.conf 인증

한눈에 보기 — 접속 → 인증 규칙 → 결과 확인

① psql 접속

docker exec · psql -U postgres

② pg_hba.conf

위에서부터 첫 일치 규칙

③ trust → md5

local · host 규칙 수정

④ 결과 확인

틀린 비밀번호 → FATAL

항목내용
접속 경로
  • docker exec -it rds_psql /bin/bash로 컨테이너 셸 → psql -U postgres
  • 한 줄 접속: docker exec ... env PGPASSWORD=... psql → 비밀번호를 명령행 환경변수에 넣는 건 실습용 (셸 기록·프로세스 환경 노출 주의)
  • SQL 프롬프트 종료 \q
trust의 범위
  • psql -U postgres -W가 비밀번호를 물어도, 컨테이너 안 Unix 소켓 접속이 기본 pg_hba.conf의 trust 규칙에 걸리면 비밀번호를 검증하지 않을 수 있음
  • 모든 외부 TCP 연결이 무인증이라는 뜻은 아님 → 실습 화면의 host all all all scram-sha-256 규칙은 TCP 연결에 비밀번호 인증 요구
규칙 순서위에서부터 먼저 일치하는 항목 적용
규칙 열 의미local = Unix socket / host = TCP / 주소 = 허용할 클라이언트 범위
주소 범위
  • 0.0.0.0/0 = 모든 IPv4 → 외부 노출 범위가 넓으므로 실습 외에는 접속 원본 제한
  • IPv6 loopback ::1/128도 별도 규칙 → 외부 IPv6 허용 여부도 따로 검토
md5와 실제 확인
  • 실습에서 로컬·TCP 규칙의 trust → md5로 바꿔 비밀번호 인증 확인
  • 저장된 비밀번호 형식·서버 설정에 따라 SCRAM 인증이 협상될 수 있음 → 실제 동작은 결과로 확인: 틀린 비밀번호 → FATAL: password authentication failed for user "postgres", 맞는 비밀번호 → 접속
# [호스트 리눅스 · root]
# 컨테이너 셸 진입
docker exec -it rds_psql /bin/bash
# [rds_psql 컨테이너 · root]
# 슈퍼유저 postgres로 접속 (종료는 \q)
psql -U postgres
# [호스트 리눅스 · root]
# 한 줄 접속 (PGPASSWORD 환경변수는 실습용, a1234는 연습값)
docker exec -it rds_psql env PGPASSWORD=a1234 psql -U postgres -d postgres

# [호스트 리눅스 · /root/rds/pg_hba.conf 파일 안]
# 표준 예시: 열 배치(TYPE DATABASE USER [ADDRESS] METHOD)는 표준 형식, 값은 실습값
# 89행: Unix socket 로컬 접속. trust → md5 (무인증 범위 축소)
local   all   all                  md5
# 91행: IPv4 TCP. 주소 127.0.0.1/32 → 0.0.0.0/0(모든 IPv4, 실습용), trust → md5
host    all   all   0.0.0.0/0      md5
# 93행: IPv6 loopback. trust → md5 (IPv6 규칙도 따로 인증 점검)
host    all   all   ::1/128        md5
# 96~98행 replication 규칙은 그대로
# 100행: TCP 일반 규칙. 기존 scram-sha-256 그대로 (넓은 주소 허용 규칙·앞선 줄 우선 적용 검토)
host    all   all   all            scram-sha-256
pg_hba.conf — 위에서부터 첫 일치 규칙 적용. local=Unix socket, host=TCP. trust는 비밀번호를 안 봄(-W로 물어도 통과 가능) → md5/scram-sha-256. 0.0.0.0/0은 모든 IPv4라 운영에서는 출발지 제한

postgresql.conf 설정·로그와 재시작 검증

한눈에 보기 — 꺼내기 → 수정 → 되돌리기 → 재시작

① docker cp

컨테이너 → 호스트 /root/rds

② 수정

postgresql.conf · pg_hba.conf

③ docker cp

호스트 → PGDATA

④ docker restart

설정 반영

⑤ 검증

docker ps -a · docker logs

항목내용
편집 위치
  • 실습의 최소 Debian 기반 이미지에는 vi가 없을 수 있음, 패키지 관리자도 dnf가 아니라 apt/apt-get 계열
  • 설정 파일은 컨테이너 /var/lib/postgresql/data/ 아래 → 호스트 /root/rds로 꺼내 수정한 뒤 되돌림
반영 조건설정 변경은 컨테이너에 복사한 뒤 재시작해야 반영
실패 시오타·잘못된 값 → 재시작 실패나 컨테이너 종료 가능 → docker ps -a와 로그 확인 → 수정본 다시 복사
정리비밀번호 실패·성공 결과를 각각 확인한 뒤 실습 컨테이너는 삭제 대신 docker stop으로 보존
# [호스트 리눅스 · root]
# PGDATA의 설정 파일을 호스트 작업 폴더로 복사해 편집
mkdir -p /root/rds
cd /root/rds
docker cp rds_psql:/var/lib/postgresql/data/postgresql.conf postgresql.conf
docker cp rds_psql:/var/lib/postgresql/data/pg_hba.conf pg_hba.conf
vi postgresql.conf
vi pg_hba.conf
# 편집본을 PGDATA 디렉터리에 되돌리고 재시작해 설정 반영
docker cp postgresql.conf rds_psql:/var/lib/postgresql/data/
docker cp pg_hba.conf rds_psql:/var/lib/postgresql/data/
docker restart rds_psql
# Up 상태 확인 → 실패하면 로그에서 오류 줄 확인
docker ps -a
docker logs rds_psql
# 실습 후 삭제하지 않고 정지로 보존
docker stop rds_psql

# [호스트 리눅스 · /root/rds/postgresql.conf 파일 안]
# 60행: 모든 컨테이너 인터페이스에서 수신 (네트워크·pg_hba 규칙과 함께 제한)
listen_addresses = '*'
# 64행: 서버 TCP 포트
port = 5432
# 65행: 최대 연결 수. 기본 100 → 30으로 줄여 메모리 사용 제한 (기본값이 틀려서 고치는 게 아니라 선택)
max_connections = 30
# 127행: DB 캐시 메모리. 화면 기본값 128MB. 메모리의 약 25%는 흔한 시작점일 뿐 고정 규칙 아님
shared_buffers = 1024MB
# 138행: 정렬·해시 연산 하나당 메모리 상한. 주석 상태여도 기본 4MB 적용
work_mem = 4MB
# 439행: stderr 로그를 파일로 수집
logging_collector = on
# 445행: 로그 폴더 (PGDATA 기준 상대 경로)
log_directory = 'log'
# 447행: 날짜·시간이 들어간 로그 파일명. 기본은 텍스트 로그 (CSV는 log_destination='csvlog' 별도 지정)
log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
# 449행: log_file_mode는 화면의 기본 퍼미션 값 그대로 둠
# 453행: 이 크기를 넘으면 새 파일로 회전. 오래된 로그 삭제가 아님 (덮어쓰기는 기본 off인 log_truncate_on_rotation에 따름)
log_rotation_size = 10MB
postgresql.conf 메모리·로그 — max_connections 100→30은 메모리 절약 선택. shared_buffers=캐시(25%는 시작점일 뿐), work_mem=정렬·해시 연산당 상한. log_rotation_size는 새 파일 회전 기준이지 삭제가 아님. 설정은 복사 후 재시작해야 반영

왜 PostgreSQL 인가

항목내용주의·이유
선택 이유가장 가볍고 켜고 끄기가 빠름실습 PC로 Oracle을 올리면 시작에 밥 먹고 와야 할 정도라 진행 불가
난이도MySQL(가장 쉽고 무난) < PostgreSQL < Oracle강사의 경험 기준 — 인프라 세팅 관점의 체감 순서
Oracle 설치oracle-database-ee-21c 같은 RPM 패키지를 제공하고 preinstall RPM을 먼저 설치100% 소스 설치가 아님 — 환경이 MySQL·PostgreSQL과 크게 달라 별도 학습 필요
Oracle 특징설치가 끝나면 설치 경로를 알려 주고, 그 경로를 기준으로 보안을 잡음DB마다 설정 파일 위치가 다르다는 점이 이후 경로 학습으로 이어짐

클라이언트 설치와 기본 버전

# [호스트 리눅스 · root]
# 클라이언트 패키지만 설치 — 기본 스트림이 13이라 개발자가 요청한 버전보다 낮음
dnf install postgresql
항목내용주의·이유
기본 결과버전 13이 설치됨지금은 그냥 설치하면 안 되는 상태 — 13은 너무 낮아 이 과정에서 쓰지 않음
개발자 요구특정 버전(예: 16)을 지정버전을 맞추지 않으면 이후 애플리케이션 연결에서 문제
선택지15·16·18 중에서 고름이 과정은 16으로 진행 (psql 16.8)

모듈 스트림으로 버전 맞추기

# [호스트 리눅스 · root]
# 설치 가능한 스트림 목록 — 15·16·18, 17은 없고 [d]가 기본(13)
dnf module list postgresql
# 설치 대상 스트림을 16으로 변경 (설치가 아니라 설치 환경 변경, 확인 질문에 y)
dnf module enable postgresql:16
# 바뀐 스트림 기준으로 설치 → 16.x
dnf install postgresql
# 모듈 설정 초기화 — 확인 질문에 y, 이후 install하면 다시 13
dnf module reset postgresql
항목내용주의·이유
enable의 의미설치가 아니라 설치 환경(스트림)이 바뀌는 동작enable만 하고 install을 하지 않으면 패키지는 그대로
reset의 결과모듈 설정 초기화 후 install하면 다시 13이 설치됨버전을 되돌릴 때 사용
화면 힌트list 출력에 enable을 넣으라는 안내가 나옴기본 스트림이 아닌 버전은 enable이 필요하다는 뜻
실수 방지확인 단계에서 n으로 중단이미 설치했다면 rpm -qa | grep postgres로 찾아 삭제 (linux.html 13장)
콜론 표기postgresql:16은 컨테이너 이미지의 이름:버전과 같은 구조모듈 이름과 스트림을 콜론으로 구분
가장 중요한 것버전 맞추기module을 모르면 구글에서 rpm 파일을 찾아 헤매게 됨
다른 계열우분투(APT)는 명령이 완전히 다름배포판별 패키지 관리 차이 (linux.html 13장)

항목내용주의·이유

인증 방식 선택

방식동작주의·이유
identOS 사용자 이름을 DB 사용자에 대응시켜 인증pg_ident.conf 매핑과 다른 서버가 있어야 쓰는 방식이라 지금은 쓰지 않음
md5비밀번호를 md5로 검증이 과정의 기본 베이스 — 지금은 이 형태만 사용
scram-sha-256SCRAM(RFC 7677) 기반 비밀번호 인증PostgreSQL 비밀번호 인증의 선택지는 md5와 scram-sha-256 두 가지 — md5는 더 이상 안전하지 않다고 안내되며 기본값은 이미 scram-sha-256
pg_ident.conf와의 관계비밀번호 인증(md5·scram-sha-256)은 pg_ident.conf와 무관map= 옵션은 ident처럼 외부 사용자 이름을 쓰는 방식에 붙는 것
없는 방식base64는 인증 방식 목록에 없음SHA-1·SHA-2·SHA-3을 고르는 방식도 아니라 SCRAM이 그 역할
pg_ident.conf 내용설명 주석과 PG user name·system user name 매핑 항목이 # 주석으로 들어 있음나중에 맵핑을 쓸 때 사용
pg_hba 5항목 — TYPE DATABASE USER ADDRESS METHOD. 0.0.0.0/0은 모든 IPv4, md5·scram-sha-256은 비밀번호 인증이며 pg_ident.conf와 무관

데몬 설정 (postgresql.conf)

# [호스트 리눅스 · /var/lib/pgsql/data/postgresql.conf 파일 안 · root]
# 60번 줄: 모든 곳에서 접속 허용 — 기본 'localhost'면 외부 접속 불가
listen_addresses = '*'
# 64번 줄: 서버 TCP 포트. 기본 5432, 다른 서비스가 쓰면 충돌
port = 5432
# 65번 줄: 최대 동시 접속 수. 1이면 한 명만 접속 가능
max_connections = 10
설정기본값·변경값주의·이유
listen_addresses기본 'localhost' → '*'기본값이면 로컬만 접속 가능해 외부·클라우드에서 접속 안 됨 — 반드시 바꿔야 하는 값
port5432 사용이미 쓰는 곳이 있으면 충돌로 기동 불가 → 여기서 변경 (MySQL 포트 변경과 같은 원리)
max_connections기본 100 → 실습 101이면 한 명만 접속하고 다른 접속은 기존이 끊겨야 함 — 서버 메모리에 맞춰 설정, 실습은 10~30이면 충분
메모리·시간 단위units 설정이 함께 있음데이터를 너무 많이 로드하면 문제가 되므로 할당량을 정하는 항목 — 지금은 건드리지 않고 AWS에서 조정
경로 설정hba_file·ident_file·data_directory는 # 주석 상태기본 경로가 아닌 곳에 두었을 때만 #을 풀어 지정 — 지금은 같은 경로라 건드리지 않음
범위모든 줄을 볼 필요 없고 중요한 줄 몇 개만나머지는 DBA가 환경을 바꿀 때 쓰는 항목, 인프라는 기본 베이스만 세팅

건드리지 않은 설정

설정내용주의·이유
tcp_keepalives_idle네트워크 활동이 없을 때 OS가 TCP keepalive 메시지를 보내기 시작하는 시간(초)0은 OS 기본값 — 접속을 강제로 끊는 시간이 아니므로 idle 세팅과 혼동 주의
authentication_timeout인증 대기 시간(1분 후 자동 종료 여부)db_user_namespace와 함께 이번 범위에서 제외
password_encryption = scram-sha-256비밀번호 저장 방식 — 이 값으로 바꾸는 경우 (기본값 이미 scram-sha-256)이것만 바꾼다고 pg_hba.conf 변경이 필수는 아님 — 업그레이드 순서는 password_encryption 변경 → 비밀번호 재설정 → 마지막에 pg_hba.conf를 scram-sha-256으로
SSL도메인과 CRT·키가 필요로컬 서버로는 불가 — 실제 AWS 환경에서 진행
shared_buffers = 128MBPostgreSQL이 자체 공유 메모리로 잡는 데이터 페이지 캐시 (최소 128kB)리눅스 free의 buffers(커널 캐시)와 다른 개념. #을 풀면 128MB를 쓰겠다는 뜻이라 가동 순간 메모리 사용량이 올라감 — 실제 메모리가 작은 이 VM에는 버퍼를 쓰는 편이 이득
temp_buffers임시 파일용 버퍼건드리지 않고 그대로 둠

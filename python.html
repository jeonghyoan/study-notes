리스트 정렬 — sort(key=lambda ...)

# [VS Code · Lambda 프로젝트 mz-apink · lambda_function.py · lambda_handler 안]
    user = [("홍길동", 55), ("강감찬", 21), ("이순신", 30)]
    user.sort(key = lambda b: b[1])   # 튜플의 1번 값(숫자) 기준 정렬
    print(user)
항목내용메모
실행 결과[("강감찬", 21), ("이순신", 30), ("홍길동", 55)]나이(튜플 1번 값) 기준 오름차순 — 셔플이 아님
용도리스트 안의 튜플·딕셔너리를 특정 값 기준으로 정렬할 때 sort 뒤에 lambda를 붙임DB 조회 결과를 특정 컬럼 기준으로 정렬하는 상황과 같은 모양
이름 규칙lambda b:의 b는 임의 이름, key는 바꾸면 안 되는 키워드key=는 각 요소에서 정렬 기준 값을 뽑아 주는 함수를 받는 키워드 인자 — 배열의 키가 아님
  • 실수 사례 1
    key를 다른 이름(예 key11)으로 바꾸면 TypeError: sort() got an unexpected keyword argument 'key11'
  • 실수 사례 2
    users.sort(...)로 써서 변수명 user와 달라 에러 → 변수명을 통일

변수에 담기·인자 받기 (3장)

  • 변수에 대입
    get_hd = lambda : 100 → get_hd()가 100 — 변수가 함수처럼 동작(익명 함수를 담은 변수)
  • 인자 받기
    sum = lambda aa, bb: aa + bb → sum(30, 50)이 80 — lambda 매개변수: 식 형태로 쓰고 호출 때 값을 넘김
  • 정의·문법
    lambda의 정의·형식·반환 규칙·AWS 서비스 Lambda와의 구분: 3장
sort(key=lambda ...) — key는 고정 키워드라 다른 이름으로 바꾸면 TypeError: sort() got an unexpected keyword argument. lambda b: b[1]은 튜플의 1번 값을 정렬 기준으로 뽑아 주는 것이라 결과는 오름차순(21 → 30 → 55)이고 셔플이 아님. 리스트 변수명과 sort를 부르는 변수명도 일치

lambda 매개변수: 반환식

파이썬의 lambda 표현식은 키워드로 만드는 익명 함수 — 서비스 이름 Lambda와는 이름만 같고 별개

항목내용메모
정의lambda 표현식 = 파이썬의 익명 함수(이름 없는 함수), def로 만든 함수는 이름 있는 함수키워드로 만드는 표현식 — 라이브러리가 아님
형식lambda 매개변수: 반환식콜론 :을 쓰는 순간 함수가 만들어짐
반환기본적으로 return — 식의 결과를 바로 반환return을 따로 쓰지 않음
쓰는 이유def 없이 한 줄로 간단히 작성sort(key=...)처럼 함수를 인자로 넘길 때
조건 처리삼항 연산 등으로 조건 처리도 가능자세한 문법은 이후 수업
서비스 Lambda와 구분AWS의 서비스 Lambda와 파이썬 lambda 식은 이름만 같고 별개Lambda 함수 안에서 lambda 식 사용은 필수 아님
# [VS Code · Lambda 프로젝트 mz-apink · lambda_function.py · lambda_handler 안]
    get_hd = lambda : 100              # 매개변수 없이 100 반환
    sum = lambda aa, bb: aa + bb       # 두 인자를 받아 합을 반환
    print(get_hd(), sum(30, 50))
lambda 표현식 — lambda 매개변수: 반환식 형태의 익명 함수이고 식의 결과가 곧 반환값. def로 만든 이름 있는 함수와 구분하고, AWS 서비스 Lambda와 파이썬 lambda 식은 이름만 같은 별개 개념

인스턴스 메서드만 있는 클래스

# [spark-master 컨테이너 · Jupyter 노트북 basic 셀 · root]
# 객체를 만들어야만 메서드를 쓰는 클래스
class test:
    def __init__(aa,name):      # 객체를 만들 때 값을 받는 초기화 메서드
        aa.name = name          # 인스턴스 변수 — 클래스 안 메서드가 같이 씀

    def test_method(aa):        # 첫 인자 aa = 인스턴스 자신(self 자리)
        print(f"{aa.name}")

z = test("apink")               # 인스턴스 생성 — "apink"가 __init__으로 들어감
z.test_method()                 # apink 출력
코드내용주의·이유
class test:클래스 정의 — 이 실습은 소문자 test클래스명은 자유, 관례는 대문자 시작
__init__인스턴스(객체)가 처음 값을 받는 곳 — test("apink")의 "apink"를 가장 먼저 받아 aa.name에 넘김값을 받는 곳이 없으면 객체 생성 단계에서 에러
첫 인자 aaself 대신 쓴 이름 — self는 관례일 뿐 고정 이름이 아니어서 임의 이름도 동작다른 사람 코드에서 self를 못 찾겠으면 첫 인자 자리를 보면 됨
aa.name클래스 안 고유 변수(인스턴스 변수) — 클래스 안 메서드들이 같이 씀객체마다 값이 따로 저장됨
ztest("apink")로 만든 객체(인스턴스) — z.test_method()로 메서드 호출인스턴스를 통해서만 쓸 수 있는 메서드라 인스턴스 메서드

__init__ 없이 test("apink")처럼 값을 넘김에러값을 받아 주는 곳이 클래스에 없음
test 없이 그냥 apink만 씀에러클래스를 호출하지 않았음
test()로 값 없이 만들고 메서드 호출에러__init__이 name 값을 요구하는데 넣지 않음
메서드(함수) 안에 아무것도 안 씀에러빈 함수는 실행 불가 — 최소 하나(예 print)를 넣어야 함
용어내용주의·이유
인스턴스 메서드첫 인자로 인스턴스(self)를 받아 인스턴스 변수를 다루는 메서드“일반 메서드”는 파이썬 공식 용어가 아님 — 문서는 인스턴스 메서드·정적 메서드·클래스 메서드로 구분
인스턴스 = 객체객체를 만드는 작업이 인스턴스 생성이고 이때 __init__이 쓰임z가 인스턴스
오버라이드부모 클래스 메서드를 자식이 다시 정의하는 심화 개념이 노트 범위 밖 — 평가 대상 아님
용어 근거파이썬 공식 문서의 클래스 장 — instance method / static method / class method로 구분“일반 메서드”는 이 구분에 없는 이름

정적 메서드 (@staticmethod)

# [spark-master 컨테이너 · Jupyter 노트북 basic 셀 · root]
# @ 로 시작하는 줄 = 데코레이터 — 아래 def 를 감싸 동작을 바꾸는 선언
# @staticmethod 는 staticmethod(함수) 호출과 같은 뜻 — 클래스·인스턴스 상태를 쓰지 않음
class test2:

    @staticmethod
    def add(a,b):
        return a+b

    @staticmethod
    def mul(c):
        return c

h2 = test2.add(3,4)     # 객체 생성 없이 클래스명으로 바로 호출
print(h2)               # 7
h = test2.mul(10)
print(h)                # 10
항목내용주의·이유
선언@staticmethod 줄이 이 메서드가 정적 메서드임을 파이썬에 알림데코레이터를 빼면 첫 인자를 인스턴스로 받는 인스턴스 메서드가 됨
데코레이터(decorator)함수·메서드를 감싸 동작을 바꾸는 파이썬 문법 — @staticmethod는 staticmethod(함수) 호출과 같음 (PEP 318)자바 어노테이션(annotation)은 코드에 붙이는 메타데이터 표기 — @ 모양만 비슷하고 같은 개념이 아님
호출클래스명 + 메서드 → test2.add(3,4)객체 생성(__init__ → 객체 → 메서드)이 필요 없음
여러 개같은 클래스에 add·mul처럼 정적 메서드를 여러 개 둘 수 있음반환값은 변수에 받아 print로 출력
특징호출할 때 받는 매개변수만 사용해 계산하고 return으로 돌려줌클래스 변수·인스턴스 변수를 참조하고 있다면 잘못 만든 것
정적 메서드 — 호출할 때 받는 매개변수만으로 계산해 return. 클래스 변수·인스턴스 변수를 참조하면 정적 메서드가 아니므로, 첫 인자와 참조 변수를 먼저 확인

클래스 변수

항목내용주의·이유
정의클래스 몸통에 바로 선언한 변수(c = 5) — 그 클래스의 모든 메서드에서 읽을 수 있음인스턴스 변수(self.name)와 달리 객체마다 따로 생기지 않음
접근 방법cls.c·클래스명.c·self.c로 접근메서드 안에서 c만 쓰면 NameError — 클래스 변수는 클래스 이름공간에 속하고 클래스 본문 스코프가 메서드로 이어지지 않음
전역 변수와 차이전역 변수가 아니라 클래스에 묶인 변수모듈 전역 이름과 같은 이름을 써도 서로 다른 값

클래스 메서드 (@classmethod)

# [spark-master 컨테이너 · Jupyter 노트북 basic 셀 · root]
# @classmethod — 첫 인자로 인스턴스가 아니라 클래스 자체(cls)를 받음
class test3:
    c = 5  # 클래스 변수

    @classmethod
    def get_data(cls):      # cls.c 로 클래스 변수를 바로 읽음
        return cls.c

    @classmethod
    def put_data(cls):
        return cls("cccddd")  # cls(...) = 새 인스턴스 생성
항목내용주의·이유
선언@classmethod 데코레이터를 def 위에 붙임정적 메서드와 모양은 같고 첫 인자만 다름
첫 인자 cls인스턴스가 아니라 클래스 자체를 받음cls는 관례 이름 — 다른 이름도 동작
용도클래스 변수를 다루거나 새 인스턴스를 만들어 돌려주는 데 씀cls("cccddd")는 클래스를 함수처럼 호출해 인스턴스를 만드는 것
변수 접근클래스명 없이 cls.c로 클래스 변수를 바로 가져옴인스턴스를 만들지 않아도 클래스 변수 확인 가능
메서드 이름get_data·put_data는 임의로 지은 이름기능을 드러내는 이름이면 충분
데코레이터 조합여러 데코레이터를 겹쳐 쓸 수 있음앞에 무엇을 쓰느냐에 따라 동작이 달라짐

인스턴스 생성과 __init__이 필요한 이유

단계할 일이유
1k = test3("hong")처럼 값을 넘기는 코드값을 받는 곳이 필요 — __init__이 없으면 에러
2__init__(self,name) 추가 후 self.name = name으로 저장넘긴 값을 객체 안에 보관
3클래스 변수를 c = 0으로 두고 __init__ 안에 test3.c += 1객체가 만들어질 때마다 전체 개수를 셈
4put_data()는 인자 없이 호출하고 cls("cccddd")로 새 인스턴스를 만들어 반환클래스 메서드가 인스턴스 공장 역할을 하는 형태

카운팅 실습 — 인스턴스를 만들 때마다 클래스 변수 증가

# [spark-master 컨테이너 · Jupyter 노트북 basic 셀 · root]
class test3:
    c = 0  # 클래스 변수 — 객체 수를 세는 값

    def __init__(self,name):
        self.name = name
        test3.c += 1        # 객체가 생길 때마다 1 증가

    @classmethod
    def get_data(cls):
        return cls.c

    @classmethod
    def put_data(cls):
        return cls("cccddd")   # 새 객체를 만들어 돌려줌 — 호출하면 카운트도 증가

k  = test3("hong1")
k2 = test3("hong2")
k3 = test3("hong3")
k4 = test3("hong4")
#kk = test3.put_data()   # 주석을 풀면 객체가 하나 더 생겨 5가 됨
print(test3.get_data())  # 4 출력
실행결과이유
객체 2개 생성 후 get_data()20에서 시작해 두 번 증가
k~k4 4개 생성4객체 수와 클래스 변수가 같아짐
#kk 주석 해제5cls("cccddd")로 인스턴스가 하나 더 생김
흐름인스턴스 생성 → __init__의 test3.c += 1 → get_data()가 증가한 값 반환접속자 수를 세는 방식과 같은 구조
클래스 변수로 개수 세기 — __init__에서 test3.c += 1, 읽을 때는 cls.c. 객체를 만든 곳이 아니어도 클래스 이름으로 읽으면 전체 개수가 나오고, cls(...)를 호출하는 순간에도 개수가 늘어남

세 가지 메서드 비교

구분인스턴스 메서드정적 메서드클래스 메서드
선언그냥 def@staticmethod 아래에 def@classmethod 아래에 def
첫 인자인스턴스(self, 이 실습은 aa)없음 — 필요한 매개변수만클래스 자신(cls)

세 메서드 구분 — 첫 인자가 무엇을 받는지가 기준. 인스턴스 메서드는 self, 정적 메서드는 인자 없음, 클래스 메서드는 cls. 정적 메서드와 클래스 메서드의 차이가 평가에서 갈리는 지점

아키텍처 용어 — Master·Driver·Executor·Task

아키텍트가 쓰는 용어와 다른 부분이 있어 소통을 위해 정리 — 같은 대상을 다른 이름으로 부르는 경우가 많음.

용어뜻메모
Master 서버마스터아키텍트도 같은 용어로 부름
Slave 서버= Worker아키텍트가 slave라고 하면 워커로 이해
DriverSpark 프로그램을 받아 전체 애플리케이션을 실행하는 총괄 프로세스"Spark 드라이버 구축"이라는 말의 대상. 자동차·C 드라이버와 무관한 IT 용어
Task드라이버가 각 워커 노드의 executor에 할당하는 작업 단위task 할당이 드라이버의 주요 역할
Executor일꾼 — CPU core에 맞춰 작동하고, 몇 개 띄울지·어떤 작업을 수행할지 결정 (스타크래프트의 SCV 비유)코어 개수에 맞춰 동작

애플리케이션 실행 순서

① 제출

spark-submit

② 드라이버

main() 실행 · SparkContext

③ 마스터

executor 자원 할당

④ task 분배

드라이버가 스케줄

⑤ 연산

executor가 코어·메모리로 실행

드라이버가 main()을 실행하고 SparkContext로 task를 스케줄 — 마스터는 executor 자원을 할당하는 역할만 담당하고, executor(일꾼) 수를 확인해 각자 얼마나 가져갈지 계산하는 것이 task 할당

용어 구분 — Slave=Worker, Driver=전체 애플리케이션을 실행하는 총괄 프로세스, Executor=코어 단위 일꾼, Task=executor에 내려가는 작업 단위. 마스터는 start·stop과 자원 할당, 연산은 워커의 executor

노드·클러스터 용어 — 개발자와 인프라

같은 "노드"라도 분야마다 다른 대상을 가리켜 개발자와 이야기할 때 부딪힘 — 대화 전에 어느 쪽 의미인지 구분.

구분뜻메모
개발자의 노드Node.js, 자료구조(링크드 리스트)의 노드Node.js는 브라우저 밖에서 JavaScript를 실행하는 오픈소스 런타임 환경(언어는 JavaScript) — 스크립트 언어라는 표현은 정확하지 않음
인프라의 노드분산 컴퓨팅 시스템(클러스터)을 이루는 컴퓨터(서버) 1대 — master node·worker node시스템을 이루는 한 부분(파트)
같은 말worker node = slave node연식 있는 인프라 담당자는 slave node로 부름
실습 서버Node.js도 이미 설치돼 있음개발자 관점과 무관 — 인프라 용어와 다른 층
두 의미전혀 무관개발자와 마스터·워커 이야기가 통하지 않고 부딪히는 이유
용어내용주의·이유
클러스터독립된 여러 대의 컴퓨터(노드)를 고속 네트워크로 연결해 하나처럼 쓰는 방식노드=컴퓨터=서버. 마스터 노드=마스터 서버, 워커 노드 2개=워커 서버 2대 (2장)
노드의 역할클러스터를 이루는 개별 머신클러스터 전체를 제어·관리하는 두뇌 역할은 컨트롤 플레인(마스터 쪽 구성요소)이 맡음 — 출처: Kubernetes 문서
컨트롤 플레인 구성설명

키 전송 (ssh-copy-id)

Spark가 마스터·워커를 IP가 아닌 이름으로 찾아야 하므로 /etc/hosts 등록(아래)과 키 배포가 한 쌍. hosts가 등록된 상태에서 키가 서로 오갈 수 있음. 순서는 자기 서버 먼저 → 상대 서버.

# [마스터 · sparkuser · 워커에서도 sparkuser로 똑같이 실행]
ssh-copy-id sparkuser@spark-master   # 자기 서버에 내 공개 키 등록 (자기 자신도 키 인증 대상)
ssh-copy-id sparkuser@spark-worker   # 상대 서버 sparkuser의 authorized_keys에 공개 키 추가

원인

확인결과판단
오타 점검.bashrc·spark-env.sh의 경로를 다시 확인경로 표기는 정상 — 오타 문제가 아님

spark.sql.shuffle.partitions — 셔플 조각 수

항목내용주의·이유
의미조인·group by·window 함수 등 데이터를 재배치하는 연산(셔플)에서 데이터를 몇 조각으로 쪼개 병렬 처리할지 정하는 값조각이 적으면 코어를 놀리고, 너무 많으면 작은 작업이 늘어남
이번 값8조각CPU·메모리가 적은 실습 클러스터 기준 — 자원이 많으면 더 크게
같은 효과distinct 등 함수도 데이터 재배치를 일으킴중복 제거도 셔플이라는 뜻 — 파티션 수 설정이 함께 영향
선행 지식MySQL의 join·group by를 알아야 이해됨이후 더 다루는 내용 — 여기서는 셔플의 조각 수로만 이해
# [마스터 · /home/sparkuser/movie.py 파일 안 · sparkuser]
# 셔플(조인·group by·window)에서 데이터를 8조각으로 나눠 병렬 처리 — 실습 클러스터 자원 기준
    .config("spark.sql.shuffle.partitions", "8")
셔플 파티션 — spark.sql.shuffle.partitions는 조인·group by·window 함수·distinct처럼 데이터를 재배치할 때 쓸 조각 수. 이 환경은 코어·메모리가 적어 8, 자원이 많으면 크게

에러: numPartitions와 분할 컬럼

항목내용주의·이유
증상RDD에서 "레코드 수 / 파티션 수가 안 맞는다"는 에러 — 81~82번 줄 df read 부분읽기 단계에서 터지므로 코드 아래쪽 집계는 실행되지 않음
원인AI가 만든 JDBC 읽기에 numPartitions·partitionColumn·lowerBound·upperBound가 있는데 분할 기준 컬럼(id)이 테이블에 없음박스오피스 테이블에는 id 컬럼이 없음 — AI가 일반적인 예제를 그대로 넣은 경우
해결위 4개 옵션을 삭제하면 정상 동작우선 작동 여부가 중요 — 병렬 읽기 튜닝은 그 뒤
옵션 규칙numPartitions를 쓰려면 partitionColumn(숫자·날짜 컬럼)·lowerBound·upperBound가 같이 지정돼야 함Spark JDBC 데이터소스 문서 — 하나라도 빠지면 병렬 읽기 구성이 성립하지 않음
JDBC 병렬 읽기 — numPartitions는 partitionColumn·lowerBound·upperBound와 함께 써야 하고, 기준 컬럼이 테이블에 실제로 있어야 함. 없으면 4개 옵션을 지우고 단일 파티션으로 읽기

# 기반 OS 이미지 (각자 만든 Rocky 9 이미지)
FROM mzleejh/apink_rocky:9
# -y 자동 승인 / --allowerasing: 의존성 충돌 시 기존 패키지 제거·교체 허용 (Rocky 9의 curl-minimal ↔ curl 충돌 사례)
# java-17-openjdk-devel: Java 17 + 개발 도구 javac / curl·tar: 다운로드·압축 해제 / python3·python3-pip: PySpark·Jupyter용
# 여러 줄은 역슬래시로 연결, && 앞뒤 공백 / dnf clean all: 캐시 정리로 이미지 크기 감소
RUN dnf install -y --allowerasing java-17-openjdk-devel \
 curl tar python3 python3-pip && dnf clean all
# Java 설치 경로
ENV JAVA_HOME=/usr/lib/jvm/java-17-openjdk
# 받을 배포본 선택값 (버전을 바꿀 때는 이 값만 바꿔 URL 관리)
ENV SPARK_VERSION=3.5.3
ENV HADOOP_VERSION=3
# Spark 설치 경로
ENV SPARK_HOME=/opt/spark
# Spark·Java의 bin을 PATH에 추가 → 어느 경로에서나 실행. ENV 이름=값은 등호 주변을 붙여 씀
ENV PATH=$SPARK_HOME/bin:$JAVA_HOME/bin:$PATH
# 아카이브를 받아(curl -sL) 파이프로 압축 해제 (x 풀기, z gzip, -C 대상 경로) → spark-3.5.3-bin-hadoop3를 /opt/spark로 이동
# ${변수}: 뒤에 다른 글자가 이어질 때 변수 경계 표시 (독립 변수는 $변수)
RUN curl -sL https://archive.apache.org/dist/spark/spark-${SPARK_VERSION}/spark-${SPARK_VERSION}-bin-hadoop${HADOOP_VERSION}.tgz | tar -xz -C /opt/ && mv /opt/spark-${SPARK_VERSION}-bin-hadoop${HADOOP_VERSION} $SPARK_HOME
# 컨테이너 기본 작업 경로
WORKDIR $SPARK_HOME
